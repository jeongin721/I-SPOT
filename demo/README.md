# I-SPOT 시연 안내 (`demo/1001` 브랜치)

다솔 님 화면(`ispotvscode`)에 Backend 를 연결한 상태로 시연한다.
STT · AI 는 mock 이라 설치가 끝나면 인터넷 없이 돌아간다. 데이터는 전부 합성이다.

## 준비물

- Windows 10 / 11
- Python 3.11 ~ 3.13 (https://www.python.org/downloads/ , 설치 첫 화면에서 **Add python.exe to PATH** 체크)
- Node.js 22 LTS (https://nodejs.org/)
- 인터넷: 설치할 때만 필요하다

## 1. 받기

짧은 경로에 받는다(예: `C:\ispot-demo`). 경로가 길면(OneDrive 안 등) 음성 업로드가 실패해서 설치가 미리 멈춘다.

- Git 이 있으면
  ```
  git clone -b demo/1001 https://github.com/jeongin721/I-SPOT.git C:\ispot-demo
  ```
- Git 이 없으면: GitHub 에서 브랜치를 `demo/1001` 로 바꾸고 **Code → Download ZIP** 으로 받아 `C:\ispot-demo` 에 푼다.
  보안 경고가 뜨면 **실행** 을 누른다(풀기 전에 ZIP 속성에서 **차단 해제** 를 체크하면 뜨지 않는다).

## 2. 설치 (한 번만)

`demo\setup.cmd` 를 더블클릭한다. 처음에는 2~5분 걸린다.
끝나면 로그인 정보가 나오고, 시연 데이터(사례 6건, 상태별 1건씩)와 업로드용 무음 파일 `demo\sample-audio.wav` 가 만들어진다.

## 3. 실행

`demo\start.cmd` 를 더블클릭한다. 창 두 개(**I-SPOT Backend**, **I-SPOT Frontend**)가 뜨고 브라우저가 열린다.
끌 때는 두 창을 닫는다.

- 화면: http://localhost:5173
- 로그인: `counselor@ispot.example.com` / 비밀번호는 setup · start 창에 나온다(저장소에 공개된 개발용 데모 값)
- 관리자 계정으로는 시연하지 않는다(관리자 화면은 아직 가짜 데이터다).

## 4. 시연 순서 (5~7분)

| 순서 | 누를 곳 | 보여 줄 것 |
| --- | --- | --- |
| 1 | 로그인 | 대시보드: 전체 담당 사례 6, 미처리 업무 5 (서버 데이터) |
| 2 | 왼쪽 **통합 사례 목록** → **새 사례 등록** → 아동 이름(예: 아동_시연01) · 연령 · 보호자 → **사례 등록** | 목록 맨 위에 새 사례가 생긴다 |
| 3 | 왼쪽 **상담 자료 검수** → **상담 자료 업로드** → 새 사례 선택 → **다음** → 새 상담 회차 → **다음** → 음성 파일 → **다음** → **파일 선택**(`demo\sample-audio.wav`) → **업로드** | 회기가 만들어지고 원문 변환이 끝나면 STT 검수 화면으로 넘어간다 |
| 4 | STT 검수: 노란 줄(검수 필요) 하나에서 **수정** → 문장 고치기 → **저장 및 확정** | "발화를 수정했습니다", 수정됨 표시 |
| 5 | **전체 확정** → **STT 검수 완료** → **완료** | 분석 결과 검토 화면으로 넘어간다 |
| 6 | **AI 분석 요청** | 몇 초 뒤 상담일지 초안 · 근거 발화 · 참고 안내가 나온다 |
| 7 | **검토 완료** → **검토 완료** → **상담일지 작성** | 승인된 요약으로 상담일지 초안이 만들어진다 |
| 8 | 오른쪽 근거 **00:02 · 00:08 · 00:14** 를 하나씩 눌러 **확인 완료 (상담사 확인)** → **상담일지 저장** → **저장** | "상담일지가 저장되었습니다" |
| 9 | 왼쪽 **대시보드** | 전체 담당 사례 7, 최근 상담 사례 맨 위에 새 사례 |

## 5. Backend 가 연결된 것을 보여 주는 방법

- **새로고침 · 다시 로그인**: 방금 만든 사례와 상태가 그대로 남아 있다(DB 에 저장됨).
- **I-SPOT Backend 창**: 화면을 누를 때마다 `POST /api/v1/cases 201` 같은 요청 줄이 찍힌다. 브라우저 옆에 띄워 두면 좋다.
- **F12 → Network → Fetch/XHR**: `/api/v1/...` 요청과 응답 JSON 이 보인다.
- **API 문서** http://localhost:8000/docs : 인터넷이 있어야 화면이 뜬다. `POST /api/v1/auth/login` 으로 받은 `access_token` 을 **Authorize** 에 넣고 `GET /api/v1/cases` 를 실행하면 화면과 같은 사례가 나온다.

## 6. 미리 알아 둘 것

- STT · AI 는 mock 이다. 어떤 음성을 올려도 같은 예시 문장과 분석이 나온다. "연결 구조 시연"이라고 소개한다.
- 아직 가짜인 화면: 사례 관리의 계획 · 종결, 보고서 생성, 관리자 화면. 대시보드의 "오늘 예정 상담 · 작성 대기 문서"는 "아직 서버에 없음"으로 나온다.
- 사례 목록의 위험도 "확인 완료"는 기본값이다(서버에 위험도가 아직 없다).
- 서버를 켠 뒤 처음 여는 화면은 2~3초 걸린다. 사람들 앞에 서기 전에 대시보드 · 통합 사례 목록 · 상담 자료 검수를 한 번씩 눌러 둔다.

## 7. 시연 전에 데이터 되돌리기

리허설로 사례가 늘었으면: 서버 창 두 개를 닫는다 → `demo\reset.cmd` → `demo\start.cmd`.

## 8. 문제 해결

| 증상 | 해결 |
| --- | --- |
| `Python 3.11 - 3.13 is not installed` | python.org 에서 3.13 을 설치하고 PATH 를 체크한 뒤 창을 새로 연다 |
| Node.js 버전 오류 | Node.js 22 LTS 를 설치한다 |
| "이 폴더 경로가 너무 깁니다" | `C:\ispot-demo` 처럼 짧은 경로로 폴더를 옮긴다 |
| "서버가 뜨지 않았습니다" | 두 서버 창의 메시지를 본다. 8000 · 5173 포트를 쓰는 다른 프로그램(다른 I-SPOT 실행 등)을 끈다 |
| "시연 서버가 켜져 있습니다" (reset 중) | 서버 창 두 개를 닫고 다시 실행한다 |
| 로그인이 안 됨 | `demo\reset.cmd` 로 계정을 다시 만든다 |
| 음성 업로드 실패 | `.wav` · `.mp3` · `.m4a` 만 올릴 수 있다 |

설정은 `backend\.env.demo` 에 따로 두므로 원래 `backend\.env` 는 건드리지 않는다.
`.env.demo` · `demo.db` · `.demo-storage` · `sample-audio.wav` 는 커밋되지 않는다.
