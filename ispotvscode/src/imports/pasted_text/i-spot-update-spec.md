I-SPOT 기존 프로젝트를 유지한 상태에서 아래 항목만 최소 범위로 수정한다.

중요:
이번 작업은 전체 UI 리디자인이나 전체 코드 재생성이 아니다.
현재 Figma Make 프로젝트의 기존 컴포넌트, 레이아웃, 스타일,
라우팅 및 mock data 구조를 최대한 그대로 재사용한다.

크레딧 사용량을 최소화하기 위해 아래에서 명시한 화면과 기능만 수정한다.

수정 대상:
1. 녹음 기능 제거
2. 상담 자료 업로드 Flow 수정
3. 통합 사례 목록의 새 사례 등록 기능 구현
4. 사례 상세의 '목록' 화면을 자료/문서 목록으로 변경

그 외 화면은 수정하지 않는다.

기존 Navy Sidebar / White Content / Gray Background 스타일을 유지하고
새로운 디자인 시스템이나 불필요한 컴포넌트를 생성하지 않는다.


━━━━━━━━━━━━━━━━━━━━
1. 녹음 기능 제거
━━━━━━━━━━━━━━━━━━━━

I-SPOT 내부에서 직접 상담을 녹음하는 사용자 기능을 제거한다.

사용자에게 노출되는 다음 기능을 제거한다.

- 상담 녹음 메뉴
- 녹음 시작
- 녹음 일시정지
- 녹음 종료
- 마이크 권한 요청
- 직접 녹음 화면
- 직접 녹음 화면으로 이동하는 버튼 및 링크

상담 음성은 I-SPOT에서 직접 녹음하지 않고
외부에서 녹음한 파일을 업로드하는 방식으로만 처리한다.

새로운 녹음 기능을 만들지 않는다.

기존 다른 기능에 영향을 주지 않는 범위에서
녹음 관련 사용자 진입 경로와 UI를 제거한다.


━━━━━━━━━━━━━━━━━━━━
2. 상담 자료 검수 화면
━━━━━━━━━━━━━━━━━━━━

기존 상담 자료 검수 화면의 전체 구조는 유지한다.

화면 우측 하단에 다음 버튼을 추가하거나
기존 업로드 버튼이 있다면 해당 버튼을 수정한다.

[ + 상담 자료 업로드 ]

Primary Blue 버튼으로 표시하되
화면에서 과도하게 크게 만들지 않는다.

버튼을 클릭하면 바로 파일 선택창을 열지 않는다.

반드시 다음 순서로 진행한다.

상담 자료 업로드
→ 사례 선택
→ 상담 회차 확인
→ 업로드 유형 선택
→ 파일 업로드


━━━━━━━━━━━━━━━━━━━━
3. 상담 자료 업로드 - STEP 1 사례 선택
━━━━━━━━━━━━━━━━━━━━

[ + 상담 자료 업로드 ] 클릭 시
먼저 Modal을 표시한다.

Modal 제목:

상담 자료 업로드

첫 화면에서는 파일 업로드보다 먼저
연결할 사례를 선택한다.

기존 CASES 데이터를 재사용한다.

사례 선택 목록에는 최소 정보만 표시한다.

- 아동 이름
- 사례번호
- 담당 상담사
- 현재 상담 회차

상단에 간단한 검색 입력창을 제공한다.

검색 기준:
아동 이름 또는 사례번호

예:

연결할 사례 선택

[ 이름 또는 사례번호 검색 ]

○ 김민지
  C-2026-0412
  담당 상담사 이서연 · 7회차

○ 박서준
  C-2026-0389
  담당 상담사 정다솔 · 4회차

사례 선택 후:

[다음]

버튼을 누른다.

사례를 선택하지 않은 상태에서는
다음 단계로 진행할 수 없다.


━━━━━━━━━━━━━━━━━━━━
4. 상담 자료 업로드 - STEP 2 상담 회차
━━━━━━━━━━━━━━━━━━━━

선택한 사례를 상단에 표시한다.

예:

김민지
C-2026-0412

연결할 상담 회차를 확인하거나 선택할 수 있게 한다.

기존 상담 회차가 있다면 선택 가능하게 하고,
필요하면 '새 상담 회차'를 선택할 수 있도록 한다.

예:

상담 회차

[ 7회차 ▼ ]

또는

[ + 새 상담 회차 ]

불필요하게 별도의 큰 페이지를 만들지 말고
동일 Modal 내부에서 처리한다.


━━━━━━━━━━━━━━━━━━━━
5. 상담 자료 업로드 - STEP 3 업로드 유형
━━━━━━━━━━━━━━━━━━━━

사례와 상담 회차가 결정되면
업로드 유형을 선택한다.

두 가지 옵션만 제공한다.

[ 음성 파일 ]
MP3 / M4A / WAV

[ 문서 파일 ]
PDF / HWP / HWPX / TXT / DOCX

두 영역은 동일한 크기로 표시한다.

과도한 아이콘,
Illustration,
Gradient,
여러 색상의 Card를 사용하지 않는다.

단순한 Border 기반 선택 영역으로 구성한다.


━━━━━━━━━━━━━━━━━━━━
6. 파일 선택 및 업로드
━━━━━━━━━━━━━━━━━━━━

업로드 유형을 선택하면
파일 선택 영역을 표시한다.

상단에는 현재 연결 정보를 계속 보여준다.

예:

연결 사례
김민지 · C-2026-0412

상담 회차
7회차

자료 유형
음성 파일

[ 파일 선택 ]

선택한 파일:
counseling_20260914.m4a

[이전]
[업로드]

업로드 완료 시 해당 사례와 상담 회차에
자료가 연결된 것처럼 mock state를 업데이트한다.

실제 backend API가 없다면
새 API endpoint를 만들지 않는다.

현재 프로젝트의 local/mock state만 사용한다.


━━━━━━━━━━━━━━━━━━━━
7. 사례 상세에서 업로드하는 경우
━━━━━━━━━━━━━━━━━━━━

사례 상세 화면의 자료 목록에서

[ + 새 문서 업로드 ]

또는 자료 업로드 버튼을 선택한 경우에는
이미 현재 사례가 결정되어 있다.

따라서 사례 선택 STEP을 생략한다.

예:

김민지 · C-2026-0412 상세
→ 새 문서 업로드
→ 김민지 자동 선택
→ 상담 회차 확인
→ 파일 유형/파일 선택
→ 업로드

현재 사례를 다시 검색하게 만들지 않는다.


━━━━━━━━━━━━━━━━━━━━
8. 통합 사례 목록 - 새 사례 등록
━━━━━━━━━━━━━━━━━━━━

현재 통합 사례 목록에 존재하는

[ + 새 사례 등록 ]

버튼에 실제 interaction을 추가한다.

버튼 클릭 시
'새 사례 등록' Modal 또는 compact form을 연다.

기존 페이지 디자인은 변경하지 않는다.


━━━━━━━━━━━━━━━━━━━━
9. 새 사례 등록 입력 정보
━━━━━━━━━━━━━━━━━━━━

새 사례 등록 Form에는 다음 정보만 사용한다.

직접 입력:

1. 이름
2. 연령
3. 보호자

자동 입력:

4. 담당 상담사
5. 상담 회차
6. 최근 상담


입력 UI 예시:

새 사례 등록

아동 이름 *
[                    ]

연령 *
[                    ]

보호자 *
[                    ]

담당 상담사
[ 현재 로그인 상담사 이름 ]
자동 입력

상담 회차
[ 0회 ]
자동 관리

최근 상담
[ 상담 기록 없음 ]
자동 관리

[취소] [사례 등록]


━━━━━━━━━━━━━━━━━━━━
10. 자동 입력 규칙
━━━━━━━━━━━━━━━━━━━━

담당 상담사:

현재 로그인되어 있는 상담사 정보를 사용하여
자동으로 입력한다.

사용자가 직접 입력하지 않는다.


상담 회차:

신규 사례 등록 시 기본값은

0회

또는 현재 프로젝트 데이터 구조에 맞는 초기값으로 설정한다.

이후 새로운 상담이 추가될 때마다 자동 증가한다.

예:

첫 상담 등록 → 1회
두 번째 상담 등록 → 2회


최근 상담:

신규 사례 등록 시

상담 기록 없음

으로 표시한다.

상담이 추가되면
가장 최근 상담 날짜를 자동 표시한다.

예:

최근 상담
2026-09-14

기존 mock data 구조를 최대한 재사용한다.


━━━━━━━━━━━━━━━━━━━━
11. 필수 입력 Validation
━━━━━━━━━━━━━━━━━━━━

다음 항목은 필수 입력이다.

- 이름
- 연령
- 보호자

입력되지 않은 경우
사례 등록을 완료하지 않는다.

과도한 오류 Modal을 사용하지 말고
해당 입력창 아래에 간단한 validation 메시지만 표시한다.

예:

이름을 입력해주세요.


━━━━━━━━━━━━━━━━━━━━
12. 사례 등록 완료
━━━━━━━━━━━━━━━━━━━━

[사례 등록] 클릭 시

입력한 정보로 새 사례를 local/mock state에 추가하고
통합 사례 목록에 새 사례가 표시되도록 한다.

등록된 사례를 선택하면
기존 사례와 동일한 사례 상세 화면으로 이동할 수 있어야 한다.

실제 backend가 없다면
페이지 새로고침 이후 데이터 영속성을 임의로 구현하지 않아도 된다.


━━━━━━━━━━━━━━━━━━━━
13. 사례 상세의 '목록' 화면 변경
━━━━━━━━━━━━━━━━━━━━

통합 사례 목록
→ 사례 선택
→ 사례 상세

진입 후 나타나는 기존 '목록' 화면을 수정한다.

현재 해당 화면에 표시되는 다음 기능은 제거한다.

- 사례관리 계획
- 종결·가정복귀 검토
- 보고서 생성

이 기능들을 이 화면의 바로가기 또는 목록 항목으로 표시하지 않는다.


━━━━━━━━━━━━━━━━━━━━
14. 사례 상세 '목록'의 새로운 역할
━━━━━━━━━━━━━━━━━━━━

해당 화면은

'이 사례와 관련된 자료 및 문서'

를 확인하는 화면으로 변경한다.

제목:

사례 자료

또는

관련 자료

선택된 아동 정보를 상단에 간단히 유지한다.

예:

김민지
C-2026-0412

그 아래 해당 사례에 업로드된 자료 목록을 표시한다.


━━━━━━━━━━━━━━━━━━━━

━━━━━━━━━━━━━━━━━━━━

목록에서는 다음 종류의 자료를 함께 보여준다.

- 음성 파일
- PDF

- 기타 현재 지원하는 상담 자료

불필요한 카드 UI를 만들지 않는다.


━━━━━━━━━━━━━━━━━━━━
16. 새 문서 업로드
━━━━━━━━━━━━━━━━━━━━

자료 목록 우측 상단에

[ + 새 문서 업로드 ]

버튼을 추가한다.

이 버튼은 현재 사례가 이미 선택된 상태이므로
사례 선택 과정은 생략한다.

Flow:

새 문서 업로드
→ 상담 회차 선택
→ 파일 선택
→ 업로드

지원 문서:

PDF
HWP
HWPX
TXT
DOCX

필요하다면 기존 상담 자료 업로드 Modal을 재사용하고
문서 유형만 미리 선택된 상태로 연다.

같은 기능을 위한 별도의 새로운 Modal 컴포넌트를
중복 생성하지 않는다.


━━━━━━━━━━━━━━━━━━━━
17. 파일 다운로드
━━━━━━━━━━━━━━━━━━━━

이미 등록된 자료의 작업 영역에

[다운로드]

기능을 제공한다.

실제 파일이 연결되어 있는 mock asset이 있다면
해당 파일 다운로드를 사용한다.

실제 다운로드 가능한 파일이 없는 mock 데이터라면
존재하지 않는 다운로드 URL이나 backend API를 만들지 않는다.

프로토타입에서는 다운로드 interaction 상태만 표현한다.


━━━━━━━━━━━━━━━━━━━━
18. 기존 상담 이력과 자료 목록 구분
━━━━━━━━━━━━━━━━━━━━

'상담 이력'과 '사례 자료'는 목적이 다르므로 구분한다.

상담 이력:
- 상담 회차
- 상담일
- 상담 시간
- 상담 유형
- 담당 상담사
- 분석 상태

사례 자료:
- 음성
- 문서
- 파일명
- 연결 상담
- 업로드 날짜
- 다운로드

기존 상담 이력 기능을 삭제하지 않는다.

19. 수정하지 않을 영역
━━━━━━━━━━━━━━━━━━━━

크레딧 소모를 최소화하기 위해
이번 작업에서는 다음 영역을 재설계하지 않는다.

- 로그인
- OTP
- 대시보드
- 관리자
- 분석 결과 검토 내부 UI
- 사례관리 계획 내부 UI
- 종결·가정복귀 검토 내부 UI
- 보고서 생성 내부 UI
- 전체 색상 시스템
- 전체 Typography
- Sidebar 전체 디자인

필요한 Navigation 연결만 수정한다.


━━━━━━━━━━━━━━━━━━━━
20. 구현 우선순위
━━━━━━━━━━━━━━━━━━━━

이번 요청에서는 다음 4가지만 우선적으로 완성한다.

Priority 1
직접 녹음 사용자 기능 제거

Priority 2
상담 자료 업로드를
'사례 선택 → 상담 회차 → 파일 유형 → 파일 업로드'
순서로 수정

Priority 3
'새 사례 등록' 버튼을 실제 입력 Form과 연결

Priority 4
사례 상세의 기존 목록을
'사례 관련 자료/문서 목록 + 업로드 + 다운로드'
화면으로 변경

위 4개 작업을 완료하기 위해 필요하지 않은
다른 파일이나 화면은 수정하지 않는다.

기존 컴포넌트와 mock data를 최대한 재사용하고,
전체 프로젝트를 다시 생성하거나
대규모 refactoring하지 않는다.
