현재 제작되어 있는 I-SPOT 웹 애플리케이션을 수정한다.

기존에 적용한 다음 방향은 그대로 유지한다.

- 웹페이지 직접 녹음 기능 제거
- 음성 파일 업로드 기반 STT 처리
- MP3 / M4A / WAV 등 음성 파일 지원
- PDF / HWP / HWPX / TXT / DOCX 등 문서 파일 업로드
- 문서의 텍스트 추출 후 상담 내용 검수 및 AI 분석 진행
- 음성 자료와 문서 자료 모두
  자료 업로드 → 텍스트화 → 검수 → AI 분석 → 결과 검토
  흐름으로 통합
- 상담 자료 업로드 버튼은 STT 검수 화면 우측 하단에 배치
- 업로드 버튼 클릭 시 음성 파일 / 문서 파일 중 하나를 선택
- 분석 결과 검토에서 추가 확인 필요 발화를 강조하고 상담일지와 연결
- 주요 버튼과 화면 전환은 실제 interaction이 작동하도록 구성

기존 디자인 시스템을 전면 변경하지 않는다.
현재 I-SPOT의 Navy Sidebar, White / Light Gray Content Area,
compact table 중심의 기관용 enterprise UI를 유지한다.

주 사용자는 전문 상담사이므로
불필요한 설명 카드, 이모티콘, 과도한 아이콘,
장식적인 그래프와 다양한 색상은 사용하지 않는다.

이번 추가 수정의 핵심은

1. STT 검수 이후 업무가 끊기지 않고 자연스럽게 이어지도록 하는 것
2. 분석 결과 검토 / 사례관리 계획 / 종결·가정복귀 검토를 하나의 사례 관리 구조로 통합하는 것
3. AI가 왜 이러한 결과를 제시했는지 실제 상담 근거까지 확인할 수 있도록 하는 것
4. 현재 상담과 이전 상담을 비교할 수 있도록 하는 것

이다.

1. 상담 업무 전체 흐름 연결
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

최종 업무 흐름:

상담 자료 업로드

→ 사례관리 계획

[분석 결과 검토]

분석 결과 검토 완료 후:

[사례관리 계획으로 이동]

사례관리 계획 화면에서는 필요 시:

[종결·가정복귀 검토]

로 자연스럽게 이동할 수 있도록 한다.

하나의 사례에 대한 연속적인 업무 단계로 느껴져야 한다.

21. UX 핵심 원칙
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

모든 화면에서 상담사가 다음 질문에 바로 답을 얻을 수 있어야 한다.

1. 지금 어떤 사례를 보고 있는가?
2. 어떤 상담 회차를 기준으로 보고 있는가?
3. 현재 어떤 업무 단계인가?
4. 이 결과는 왜 나온 것인가?
5. 어떤 상담 내용이 근거인가?
6. 이전 상담과 비교하면 어떻게 변화했는가?
7. 다음 업무는 무엇인가?

이를 위해 화면 구조를

사례
→ 상담
→ 분석
→ 근거
→ 사례관리
→ 변화 비교
→ 종결 검토

순서로 일관성 있게 유지한다.

22. UI 디자인 원칙
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

전문 상담사가 사용하는 업무 시스템이므로
다음 요소는 최소화한다.

- 이모티콘
- 장식용 아이콘
- 불필요한 카드
- 설명용 큰 문구
- 컬러풀한 상태 카드
- 과도한 통계 그래프
- 불필요한 애니메이션

기본 디자인:

Dark Navy Sidebar
White Main Content
Light Gray Background
Primary Blue
Neutral Gray

위험 정보가 실제로 필요한 경우에만
Red / Amber 계열을 제한적으로 사용한다.

사례 선택 영역은 compact하게 만든다.

업무 화면에서는
Table / Tabs / Split View / Text 중심으로 구성한다.

한 화면에서 너무 많은 정보를 표시하지 말고
필요한 정보만 단계적으로 확인할 수 있도록 한다.

23. Interaction 구현
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

다음 interaction이 실제 동작하도록 한다.

- 사례 관리 메뉴 진입
- 상단 사례 선택
- 선택한 사례 변경
- 분석 결과 검토 선택
- 사례관리 계획 선택
- 종결·가정복귀 검토 선택
- 이전 상담 선택
- 상담 상세 조회
- 현재 상담과 이전 상담 비교
- 근거 보기
- 상담 원문 위치 이동
- 분석 결과에서 사례관리 계획 이동
- 사례관리 계획에서 종결 검토 이동
- 종결 판단 근거 조회
- 상담사 최종 의견 작성 및 저장

실제 backend API가 없는 기능은
존재하지 않는 API endpoint를 임의로 만들지 않는다.

local mock state를 활용해
UI interaction과 navigation만 구현한다.
