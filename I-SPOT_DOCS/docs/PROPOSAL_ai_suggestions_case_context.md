> **#93 §4 제안 B(아동 특성 · 가정상황 AI 제안)의 보류를 풉니다** — 이 문서 §2 가 그 자리를 대신합니다.

## 0. 공통 원칙

- **판단은 상담사.** 셋 다 AI 는 "이 근거로 이걸 확인해 보면 좋겠다" 까지만 하고, 상담사가 눌러야(추가 · 승인) 일지 · 브리핑에 들어갑니다. 미리 고르거나 미리 승인하지 않습니다.
- **근거는 항상.** 제안마다 근거 발화(`segment_ids` → 화면에서 'N회차 01:36 아동' · STT 검수 링크)를 붙입니다. 근거 없는 제안은 버립니다(README 원칙 3).
- **AI 표시는 항상.** 'AI 추천' · 'AI 초안' 칩(README 원칙 2).
- **"아동 정보" 의 범위**는 #93 에서 합의한 `case_context` 그대로입니다 — 나이대(`child_age_band`) · 성별 · 보호자 유형 · 초기면접 항목 · 직전 승인 회차 요약 4칸(마스킹 경유). **이름 · 생년월일 · 연락처 · 사건번호 · 메모는 OpenAI 로 보내지 않습니다.**

## 1. 공통 입력

`analyze(payload, case_context=…)` (#93 §3, 민규 님 PR 1). 아래 세 기능은 모두 이 값을 받아 씁니다. case_context 가 없으면(이전 서버 · mock) 지금처럼 녹취만 보고, 초기면접 중복 거르기 같은 사례 맥락만 빠집니다.

## 2. 요약 · 일지 > '추가로 확인한 항목'(아동 특성 · 가정상황) — AI 추천

### 화면 (10/21 디자인의 AI 제안 모양)

```
아동 특성   초기면접: 불안 · 낮은자존감
            추가로 확인한 항목: (상담사가 고른 것)
            AI 추천 ─ 우울 · 근거 1회차 01:36 아동 "요즘 아무것도 하기 싫어요"   [추가]
                     → 이 발화로 '우울' 을 확인해 보면 좋겠어요
```

- 추천은 **"추가로 확인한 항목" 에 아직 없는 서식 4 항목**만, 칸마다 최대 5개.
- `[추가]` 를 누르면 일지 초안에 들어가고(지금 고르기 단추와 같음), 저장은 상담사가 합니다.

### AI

- **새 LLM 을 만들지 않고** 이미 도는 `checklist_llm.generate_checklist_draft` 결과(`checklist_draft.checklist[]` — 서식 4 가정상황 · 아동 특성 항목별 원문 근거 발췌)를 씁니다. 지금은 Contract 에서 버려집니다.
- `contract_adapter` 경계에서 세 가지를 맞춥니다.
  1. **항목 이름**: checklist 는 띄어쓰기 없는 이름(`부부및가족갈등`, `대인관계기피(은둔형외톨이)`)이라 `backend/app/core/intake.py` 목록 이름으로 바꿉니다(공백 · 괄호 설명 무시 비교 + 표). 목록 밖 · `특성없음` · `기타` 는 버립니다.
  2. **근거 → segment_ids**: 근거는 원문 발췌 문장이라, 아동(+ 가정상황은 보호자도 — §6 질문 2) 발화 원문에서 찾아 segment_id 로 바꿉니다. 못 찾으면 그 항목을 버립니다.
  3. **초기면접 중복**: `case_context` 의 초기면접 항목은 뺍니다.
- `case_context` 를 checklist 프롬프트에도 넣어 "초기면접에 없는 새 항목" 을 찾게 합니다.

### Contract (새 선택 필드)

```jsonc
"intake_suggestions": {
  "child_traits":      [ { "item": "우울", "segment_ids": ["seg_014"], "reason": "아무것도 하기 싫다고 말함" } ],
  "family_situations": [ { "item": "알콜남용", "segment_ids": ["seg_031"], "reason": "술 마시고 오면 때린다고 말함" } ]
}
```

## 3. 추가 확인 · 질문 > '다음 상담 전 확인할 사항' — 아동 정보를 넣은 확인 메모

- 지금 `followup_check_llm` 은 녹취(아동 진술 요지 · 위험 신호 · 저신뢰 발화)만 봅니다. 여기에 `case_context` 를 넣습니다.
  - 예: 초기면접 '알콜남용' + 이번 "술 마시고 와서 때려요" → "보호자 음주 빈도 · 음주 후 상황 확인 필요"
  - 예: 직전 승인 회차 요약 "조모에게 연락하는 안전 계획" + 이번 언급 없음 → "안전 계획(조모 연락) 유지 여부 확인 필요"
- **Contract 변경 없음** — 지금 `followup_check_points[{text, segment_ids}]` 그대로입니다. 질문 문장을 만들지 않는 원칙(메모만)도 그대로.
- 근거가 지난 회차 문장뿐인 메모는 이번 회차 `segment_ids` 가 없을 수 있어, "근거 · 지난 회차 확정 요약" 표시를 허용할지 §6 질문 3.

## 4. 추가 확인 · 질문 > '추가 질문' — LLM 으로 열린 질문 만들기

### 화면 (10/27 디자인)

질문 카드: 종류 칩(`열린 질문`) · 질문 문장 · `근거 · N회차 01:08` · **[승인]**, 아래 **[+ 질문 직접 추가]** · **[수정]**. 탭 '다음 상담에서 직접' 만 이번 범위('아이 앱으로 먼저' 는 아이 앱 서버가 없어 준비 중).

### AI — 새 모듈 `followup_question_llm.py`

- 입력: 이번 회차 확인 메모(§3) · 위험 관련 발화 · 아동 진술 요지 · `case_context`(나이대 — 말투 · 어휘 수준).
- 출력: 질문 최대 5개 `{text, kind: "OPEN", segment_ids, reason}`.
- **유도 질문 막기**(아동 면담의 가장 큰 위험):
  - 프롬프트 금지: 예/아니오로 답하는 질문, 가해자 · 행위를 먼저 꺼내는 질문("아빠가 때렸어?"), 원문에 없는 사실 · 감정 가정, 한 번에 여러 질문.
  - **코드 검사**로 한 번 더 거릅니다: `~했어?/~니?/~지?` 로 끝나는 닫힌 질문 꼴, 원문에 없는 인물 · 행위 단어, 근거 `segment_ids` 없음 → 버림.
  - 아동이 실제로 한 말을 이어받는 열린 질문만("등이랑 팔이 아팠던 건 지금은 어때?").
- 같은 마스킹 경로(`mask_for_outbound` → LLM → `restore_pii`), 분석 병렬 묶음에 넣어 시간이 늘지 않게.
- 나중에 검증된 **질문 은행**이 생기면 RAG 로 섞을 수 있게 `kind` 에 `"BANK"` 와 `bank_code`(예: `QB-N-01`)를 예약해 둡니다.

### Contract (새 선택 필드) · Backend

```jsonc
"followup_questions": [
  { "text": "등이랑 팔이 아팠던 건 지금은 어때? 누가 봐 준 적 있어?", "kind": "OPEN", "segment_ids": ["seg_012"], "reason": "통증 이후 치료 여부가 안 나옴" }
]
```

- **승인 · 직접 추가 · 수정을 저장할 곳이 없습니다** → Backend 새 API 가 필요합니다(제안):
  `GET/PUT /sessions/{id}/followup-questions` — 상담사가 승인 · 고친 · 직접 쓴 질문 목록(`{text, source: AI|COUNSELOR, approved_at, segment_ids}`). AI 원본은 분석 결과에 그대로 남습니다.
- 상담 전 브리핑의 '추가 질문' 칸은 이 승인 목록을 보입니다(지금 준비 중).
